# RSS 剧集优选 1.2.0

基于 ca 上运行的 1.0.1 插件改进，覆盖查重、选集、升级、配置、审计及提交恢复。此版本不自动改动媒体库或其他插件；更新后默认只补缺集。

## 1.2.0 更新

### 集数识别更全

种子内文件名现在能识别：

| 命名 | 示例 |
|---|---|
| `E05` / `EP05` / `EP.05` / `S01EP05` | `某剧.S01EP05.2160p.WEB-DL.mkv` |
| 集数范围 | `E01-E03`、`EP01-EP03`、`S01E05-06` |
| 中文 | `第05集`、`第5话` |
| 字幕组（仅在以上都没匹配时启用） | `[Group] Show - 05 [1080p].mkv`、`[Group][Show][05][1080p].mkv`、`- 05v2` |
| 按集目录中的字幕 | `Subs/Show.S01E05/2_English.srt` 归入第 5 集 |

以前 `EP05` 和字幕组命名的整包会因“视频文件无法识别明确集数”被每轮暂缓、永远下不下来。仍保持保守：`E-AC3`、`HE 10` 之类不会被当成集数；一个文件名里出现多个裸数字（如 `[01][02]`）时拒绝猜测；`[480]`/`[720]` 不当作集数；范围目录（`S01E01-E12/`）里的字幕不会被选中。

### 防止标题虚标导致循环下载

升级模式下，候选画质只能看标题。如果某个资源标题写 2160p、实际是 1080p，以前会在保护期过后被反复判定为“升级”而重复下载（尤其是配合 qB 已整理自动清理把任务删掉之后）。

现在会记录每一集是从哪个 RSS 条目、哪个种子 Hash 下载的（补缺和升级都记）。之后同一条目或同一种子（包括其他站点的相同种子）不会再被用于这一集的“升级”，决策原因显示“疑似标题虚标”。不影响：

- 其他资源对同一集的正常升级；
- 删集后从同一资源补回缺集。

来源记录保留 180 天，每集最多 10 条。

### 决策记录不再被刷屏

- 单轮运行内的决策先缓存，结束时一次写入，不再每个候选读写一遍整份记录。
- 同一 RSS 条目的“跳过/暂缓”结果和上一次完全相同时不再重复记录（7 天后重新记录一次）。结果一变（例如从“媒体库已有”变成“查询失败”）会立即记录。
- 详情页默认只展示非“跳过”的最近 50 条，并提示隐藏了多少条“跳过”。

### 少做重复识别

已确认不适用的 RSS 条目会短期缓存，下一轮直接跳过，不再重复调用媒体识别和规则过滤：

| 原因 | 缓存时长 |
|---|---|
| 未识别到媒体信息（可能是临时网络问题） | 2 小时 |
| 未匹配适用规则组 / 不匹配规则组 | 6 小时 |
| 非电视剧、无有效数据、标题无明确集数 | 24 小时 |

修改包含/排除、规则组、大小范围等相关配置后缓存自动失效；打开“清理历史记录”也会清空缓存。需要查重和下载的条目不缓存，删集补回不受影响。

### 其他

- 待完成下载记录超过 7 天、且下载器确认任务已不存在或已完成时自动清理；下载器本身已被删除的记录 30 天后清理。下载器查询失败时保留。
- 包含/排除正则写错时，保存配置会记录错误，运行时整轮停止，而不是放宽匹配导致误下载。
- RSS 没有提供种子大小而又设置了大小范围时，记录一条说明并跳过，不再打印异常堆栈。
- 媒体服务器、下载器类型比较统一忽略大小写。
- 跨源排序和升级判断使用同一套画质解析。
- 历史页只渲染最近 100 条，并显示实际选择的集数、升级集数和下载模式（存储上限仍为 1000 条）。

## 功能

### 严格媒体库查重

绕过无法区分错误与不存在的 `media_exists()`，直接使用媒体服务器已配置的连接信息读取 Emby API。请求使用认证头，不把 API 密钥放到查询参数或本插件错误消息里。

只有成功 HTTP 状态、有效 JSON、完整 Items/TotalRecordCount 结构、稳定分页和有效季集编号才算成功。HTTP 错误、连接异常、分页不完整、同名条目缺少媒体 ID、所选服务不可用时，重试后暂缓下载。按媒体来源/ID筛选并校验命中，辅助标题查询用于发现身份不明的同名条目。合并多个剧集条目及全部版本，不用前十条搜索结果猜是否缺集。

保存已确认集数。已有集数突然减少时，需要间隔一段时间、在另一轮成功查询中确认同样的缺失结果，再允许补回；恢复正常会重置复核。每轮相同媒体复用查询，避免多个 RSS 候选重复查询和把同一轮计为两次确认。

### 更新包只选目标集数

默认只补缺集：已有 1–10 集、候选为 1–12 集时，只选择 11、12 集。

使用 qBittorrent 严格提交流程：验证种子文件 → 暂停添加 → 确认任务身份和暂停状态 → 设置目标文件与字幕优先级 → 复核实际优先级及完整集数 → 启动。保留 MoviePilot 的标签与下载路径映射，支持后续整理入库。样片、预告和无关文件不选。

文件不能明确匹配集数、一个视频同时含有旧集与缺集、缺少目标集、优先级设置失败或复核失败时，不启动整包回退。已经存在的种子任务不会被插件重启或修改。新添加但失败的任务保留暂停状态和临时标签供检查，不删除下载数据。

### 可配置的实际版本升级

默认“只补缺集”。启用升级后，比较媒体库返回的 MediaStreams/MediaSources、分辨率、HDR 和文件名来源信息，而不是把 RSS 历史质量记录当作库中版本。

- 平衡策略：分辨率与 HDR 均不下降，至少一项提升。
- 分辨率策略：只比较分辨率；用户明确选择后才使用，可能改变 HDR 版本。
- 来源策略：同时要求分辨率、HDR 和来源档次不下降。

已有多个版本时考虑全部版本；已经有同档或更好的版本时跳过。所需比较维度未知时保留已有版本。候选画质依赖 RSS/种子文件命名声明，升级提交前再检查目标文件命名是否支持该档次；没有宣称能在下载前读取远程种子视频的真实码流。

### 去重、恢复和审计

提交前先保存目标集数、种子 Hash、下载器和提交意图。进程即使在任务启动后中断，下一轮仍可按 Hash 查询实际任务。正在下载的任务始终拦截重复提交；完成但尚未入库的任务保留一段保护期。查询任务失败时暂缓，失败但仍存在的暂停任务也保留保护。

只记录实际选中的集数。旧 RSS 历史不再永久阻止主动删集后的补回；同一 RSS 记录再次成功提交时替换历史行，避免历史膨胀。清理历史不会清除正在下载的保护。

保存最近 500 条判断，插件详情页展示最近 50 条，日志记录已有、缺集、升级、待完成任务、选择集数和跳过/暂缓/失败原因。下载和订阅链继续静默，不额外发送系统通知。

## 配置默认值

| 设置 | 默认 | 行为 |
|---|---|---|
| 查重服务器名称 | 留空 | 使用全部启用服务；可逗号分隔指定名称 |
| 下载模式 | 只补缺集 | 升级必须主动开启 |
| 升级策略 | 分辨率与 HDR 平衡 | 不以文件大小作为升级理由 |
| 查询次数 | 3 次 | 可设置 1–5 次，重试间隔 1 秒 |
| 删除集数复核间隔 | 10 分钟 | 可设置 1–120 分钟 |
| 完成任务待入库保护 | 6 小时 | 可设置 1–72 小时；正在下载的任务不会仅因超时被放行 |
| 跨 RSS 优选排序 | 开启 | 关闭只影响排序，严格查重与提交保护仍启用 |
| 跳过标题无集数资源 | 开启 | 关闭后可读取种子文件确认明确单季范围 |

保留原 RSS 地址、包含/排除规则、规则组过滤、大小限制、保存路径与历史管理接口。数值范围与枚举配置会校验。原 1.0.1 的永久质量记录保留在宿主数据中但不再作为下载拦截依据；新记录使用独立版本键。

## 适用范围与实际限制

本版针对当前 ca 的 MoviePilot V3 + Emby + qBittorrent，已核对其源码、接口签名和导入兼容性。严格查重适配 Emby/Jellyfin API；Jellyfin 未实机验证。严格下载只支持 qBittorrent。明确选择了不支持的媒体服务器/下载器时暂缓处理，避免降级成不可靠查重或整包下载。

磁力链接没有可验证文件清单时暂缓；无法拆分的多集单文件、缺少明确季集信息的文件和多季包也暂缓。画质未知时不升级。适配器不删除旧版媒体文件，升级是否替换还是并存继续由 MoviePilot 整理规则决定。

真实下载、真实文件优先级修改、升级整理入库还没有在生产环境试跑；这些副作用只用测试下载器验证。服务器上的原插件、配置和已有任务未改动。

## 验证

见 [验证记录](../../tests/rss_episode_quality/VALIDATION.md)。1.2.0 本地 110 个测试通过（1.1.0 为 81 个）；使用实际宿主 Python 环境仅在内存导入本地源码，并对真实 Emby 进行只读查询。发布前没有调用新版的 init_plugin/check 或任何生产下载器写接口。

本地复跑：

```sh
python3 -m venv .venv
.venv/bin/pip install -r tests/rss_episode_quality/requirements-test.txt
.venv/bin/python -m unittest discover -s tests/rss_episode_quality -v
```

## 更新方式

在 MoviePilot V3 插件市场刷新本仓库，更新“RSS剧集优选”到 1.2.0，再保存配置。从 1.1.0 升级无需改配置，新增的数据（来源记录、跳过缓存、决策去重状态）会自动建立。默认模式为“只补缺集”；若希望升级已有版本，在配置中选择升级模式和策略。

插件目录现在包含 `__init__.py`、`engine.py`、`adapters.py`，手动安装时需要复制完整目录。保留旧 RSS 配置与历史；旧永久质量记录不再用于拦截下载。继续停用负责同一批剧集的其他下载入口，独立插件之间不共享待完成任务记录。
