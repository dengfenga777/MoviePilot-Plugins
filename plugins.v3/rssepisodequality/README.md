# RSS剧集优选

独立插件 ID：`RssEpisodeQuality`。版本：`1.0.0`。要求 MoviePilot `>= 3.0.0`。基于本仓库的无通知 RSS 插件扩展，保留原作者署名。

## 使用

1. 在 MoviePilot V3 插件市场添加本仓库，刷新后安装“RSS剧集优选”。
2. 停用负责同一批剧集的旧 RSS 下载插件或任务，避免多个下载入口同时工作。
3. 将原 RSS 地址复制到新插件，每行一个。新插件的配置和历史独立，不读取或更改其他插件的数据。
4. 检查保存目录、包含/排除条件和种子大小范围。按原配置可设置 `0-20` GB；新插件默认未设置大小范围。
5. 在 MoviePilot 配置适用于电视剧/动漫的订阅优先级规则，并选中“使用MP订阅优先级规则”。
6. 开启插件。默认动作是直接下载，也支持添加订阅；质量去重仅在直接下载时生效。默认不发送通知。

## 质量优选

先读取所有 RSS 源，并完成原有包含、排除、大小、媒体识别和订阅规则过滤，再比较有效剧集候选。以媒体来源、媒体 ID、季、集为去重依据，优先提交质量较好的版本。

优先按 MoviePilot 命中的规则分数排序（高分优先），同分再参考分辨率、片源、HDR、帧率、编码。文件大小仅作为同档候选的最后选择依据，不单独触发升级。

成功加入下载队列后，立即保存每集质量。后续同档或低档版本跳过，更高档版本可以加入队列。高档候选添加失败时，继续尝试后面的候选，不提前记录成功。

| 情况 | 处理 |
| --- | --- |
| 同集 1080p 5 GB 与 2160p 2 GB 同轮出现 | 按规则优先 2160p，跳过 1080p |
| 同档同集，不同大小或发布组 | 优先选择一个，成功添加后跳过其余同档版本 |
| 已成功添加高档版本，之后出现低档版本 | 拦截降级 |
| 已成功添加低档版本，之后出现高档版本 | 未被媒体库存在检查拦截时允许升级 |
| 高档 E01-E02 更新包与低档 E02 单集 | 先添加高档包，跳过低档单集 |
| 已有 E01-E02，又出现 E02-E03 更新包 | 因包含新增 E03，允许整个包下载；E02 可能重复 |
| 电影 | 跳过，交由电影下载插件处理 |

## 配置

- **剧集优选：同集去重，允许质量升级**（`smart_quality`）：默认开启。关闭后沿用逐条添加行为。
- **剧集优选时跳过无法识别集数的资源**（`skip_unknown_episodes`）：默认开启。标题及简介均无法识别集数的整季包、更新包或多季包不会参与下载，避免误判覆盖范围。关闭后这类资源沿用原流程，无法保证跨版本去重。
- 其他配置沿用原插件：执行周期、RSS 地址、代理、包含/排除正则、种子大小、保存目录、动作及使用订阅优先级规则。

## 记录与边界

- 本插件配置、日志、API、历史与质量记录使用独立 ID，不覆盖旧插件。
- `episode_quality_v1` 单独保存逐集成功添加记录，不受历史最多 1000 条限制。本插件保留的历史可迁移入质量记录；旧插件的历史不自动导入。
- 记录的是成功加入下载队列，并不跟踪随后下载失败、手动删除种子或文件。媒体库已存在的集沿用原插件跳过行为，不自动洗版已入库文件。
- 更新包中只要有新增或升级的集就整体允许下载，不进行种子内文件选择，因此可能少量重复。
- 优选只比较当前所有 RSS 源的同轮结果，没有等待发布窗口。高档晚于低档发布时，仍可能先后下载。
- 更高质量资源必须先满足大小等过滤条件。比如限制 `0-20` GB 时，超出 20 GB 的资源不参与选择。
- 调整质量规则后，旧质量分数不会自动重新计算。需要另行迁移或重新评分。
- 在优选下载模式使用“清理历史记录”会同时清理质量记录，可能重新添加当前 RSS 中的旧资源；不要将清理历史作为常规去重手段。
- 独立插件首次启用时无法得知旧插件已添加但还未入库的下载。切换前应检查当前队列，避免首次扫描重复添加。

## 验证

执行 `python3 -m unittest discover -s tests -v`。离线测试使用模拟 SDK、识别、规则、媒体库和下载器，不访问网络或添加真实下载。已验证跨源优选、同档不同大小、失败回退、后续升级/降级、分季分剧、更新包、历史迁移、未知集数及电影排除等行为。
